## 1. Keybinding fixes — done

### 1.1 Root cause: zsh-vi-mode reverts custom bindings set after it loads

**Root cause found**: `zsh-vi-mode` defers its own `zvm_init()` to the first `precmd`
whenever `ZVM_INIT_MODE` isn't already `sourcing` *before the module loads* — and it wasn't,
because the only place setting it (`005-fzf.zsh`) runs *after* Zim's `init.zsh` has already
sourced the module and locked in the deferred path. That meant `zvm_init()` (and its
`bindkey -v` keymap reset) ran on the first prompt, *after* `004-keybinds.zsh`'s plain
`bindkey` calls had already run — silently clobbering them.

**Fix landed**:
- `config/.config/zsh/.zshrc`: moved `export ZVM_INIT_MODE=sourcing` to just before
  `source ${ZIM_HOME}/init.zsh`, so `zvm_init()` now runs synchronously and immediately, in
  the correct order (confirmed live: `zvm_init` no longer appears in `precmd_functions` at
  all — it runs once, up front, instead of being queued).
- Verified live via a real pty (tmux) session, including a full ESC → insert-mode round
  trip: all 5 bindings (`Option+←/→`, `^F`, `^B`, `^P`, `^N`) and the `^G` unbind hold with
  the `ZVM_INIT_MODE` fix alone — no extra safety net needed.
- **Correction**: an earlier pass of this fix also added a `precmd_functions`-based
  "defense-in-depth" re-apply of the same bindings on every prompt cycle, on top of the
  `ZVM_INIT_MODE` fix. That turned out to be both unnecessary (the root-cause fix alone is
  sufficient — verified by removing the extra hooks and re-confirming all bindings/round-trip
  behavior still holds) and the actual cause of a separate bug: it interacted badly with
  zsh-autosuggestions, which re-wraps zle widgets on every precmd too — the two colliding
  every cycle left stale/uncleared text on screen after recalling a long (wrapping) history
  entry and deleting it. Removed the extra `precmd_functions` hooks entirely; `004-keybinds.zsh`
  and `005-fzf.zsh` are back to plain one-time `bindkey` calls, which now stick correctly on
  their own.

### 1.2 tmux root-table `Ctrl-H` / `Ctrl-L` swallowed outside Vim
- [x] Extended the `is_vim`/`is_fzf` guard from `C-j`/`C-k` onto `C-h` and `C-l` in
      `tmux.conf.local`. Validated via `tmux source-file` in an isolated throwaway session.

### 1.3 `Alt-F` bound twice in tmux — jump mode always wins
- [x] Rebound jump-mode to `M-g` (was colliding with `M-f` on the normal-start mode).
      First tried `M-j`, but a live `tmux list-keys` check caught that it silently collided
      with oh-my-tmux's own `M-h`/`M-j`/`M-k`/`M-l` pane-resize bindings (generated later,
      so they were winning) — corrected to `M-g` and re-verified live.

### 1.4 `tmux.nvim`'s built-in navigation duplicates hand-rolled `Ctrl-hjkl`
- [x] Added `set -g @tmux-nvim-navigation false` to `tmux.conf.local`.

### 1.5 tmux-fingers binary is broken (missing dependency)
- [x] Installed `bdw-gc` via brew; `tmux-fingers version` now reports `2.7.1` instead of
      crashing. Added `brew "bdw-gc"` and `brew "tmux-fingers"` to the Brewfile (neither was
      declared there before, so a fresh machine would have hit the same crash).

### 1.6 `<prefix> C-f` clash: `find-session` vs tmux-fingers
- [x] Confirmed live that tmux-fingers was winning `<prefix> C-f` once 1.5 was fixed, exactly
      as anticipated. Moved `@fingers-key` to `C-y` (confirmed free in the prefix table);
      `<prefix> C-f` now resolves to `find-session` again, `<prefix> C-y` to fingers.

### 1.7 tmux-session-wizard's `T` binding doesn't register at all
- [x] Investigated: `T` registers correctly in a freshly-started tmux server (confirmed
      twice, in separate throwaway sessions) and `bin/t`'s script is present and executable.
      This was a session-lifetime issue, not a config bug — a long-running server predating
      the plugin/config change wouldn't pick it up without a full restart (not just
      `source-file`). No config change needed; today's other tmux.conf.local changes require
      the same full restart anyway.

### 1.8 Decisions, not bugs — cleanup landed where applicable
- [x] Removed the dead `bindkey -e` line (`004-keybinds.zsh`) — contradicted the rest of the
      file's vi-mode bindings, zero live effect.
- `Ctrl-Y` → `copypwd` and `vicmd j`/`k` → history-substring-search remain as deliberate
  tradeoffs, unchanged.
- Corrected the `copy-mode-vi y` file attribution: the dead `send -X copy-selection-and-cancel`
  line lives in the base `config/.config/tmux/tmux.conf` (oh-my-tmux upstream), not
  `tmux.conf.local`. Left as-is (tmux-yank's override already makes the functional outcome
  the same either way) — this was a documentation correction, not a functional change.

## 2. `install.sh` rewrite — done

- [x] Every step now runs via `$DIR`-prefixed paths.
- [x] Removed the duplicate `config/.config/zsh/setup.sh` call.
- [x] `common_setup()` now holds the genuinely cross-platform steps (zsh/TPM setup, rust,
      terminfo, per-app config symlinking, bin symlink, opt-in package installs);
      `darwin_setup()` is slimmed to macOS-only steps (macOS `defaults`, brew bundle); added
      a `linux_setup()` stub that's honest about not being wired up yet rather than
      pretending full Linux support exists.
- [x] Dropped `--remote` from `git submodule update --init --remote --recursive`.
- [x] `gcloud.sh` and `fzf-git.sh` are wired in as opt-in via `--with-gcloud` /
      `--with-fzf-git` / `--with-extras` flags (both are actually non-interactive as written,
      but a fresh install shouldn't be forced to pay for the download by default). `go.sh` is
      still a genuinely empty file (0 bytes) — left unwired since there's nothing in it yet.
- [x] Replaced `set +ex` with a `critical()`/`optional()` helper split: symlinking, rust,
      terminfo, and brew bundle abort the install on failure; macOS `defaults` and the
      opt-in extras warn and continue.
- [x] `setup/utils/backup.sh` is implemented for real (see §3.4) and wired into both the
      `config/.config/*` symlink loop and `config/.config/zsh/setup.sh`'s profile-dotfile
      symlinks.
- [x] Retired `setup/utils/symlinks.sh` (deleted — `*.symlink` convention was genuinely
      unused anywhere in the repo).

**Also found and fixed while implementing this** (not originally called out in this plan):
- `setup/packages/{rust,fzf-git,gcloud,go}.sh` and `setup/terminal/shell.sh` were missing
  their executable bit — `install.sh` invoking them directly (`"$DIR"/setup/packages/rust.sh`)
  would have failed with "Permission denied" on a fresh machine. Fixed via `chmod +x`.
- `config/.config/zsh/setup.sh` had a `mkdir -b` (invalid flag, not `-p`) and a doubled
  `tmux/tmux/plugins/tpm` path in its TPM git-clone target, plus its own `XGD_CONFIG_DATA`
  typo (should be `XDG_CONFIG_HOME`, and was never set, so it always silently fell back to
  the same default) — all fixed alongside its path-resolution fix (§3.2).

**Verified**: full dry run against a sandboxed fake `$HOME` (not the real machine) — real
pre-existing content gets backed up correctly before being replaced by a symlink, re-running
is idempotent (no duplicate backups once something is already a symlink into the repo), and
the per-app loop produces one symlink per `config/.config/*` entry. Did not run install.sh
against the live machine — that's a deliberate call the repo owner should trigger themselves
whenever they're ready, since it touches `~/.config` and (via `darwin_setup`) runs a full
`brew bundle`.

## 3. Repository structure & composability — done

### 3.1 Symlink each `config/.config/*` entry individually, not the whole folder
- [x] `install.sh` now loops over `config/.config/*` and symlinks each entry into
      `~/.config/` individually, backing up any real pre-existing content first.

### 3.2 Standardize path resolution — deploy everywhere
- [x] `setup/utils/dotfiles_home.sh` and `config/.config/zsh/setup.sh` no longer use the
      fragile `$2`-based pattern — both now resolve their own location via `$0`/
      `${BASH_SOURCE[0]}` and compute the repo root relative to that, matching the reliable
      idiom `install.sh` (and most other scripts in the repo, which turned out to already be
      correct) already used.
- Kept `dotfiles_home.sh` as a shared helper rather than deleting it outright (deviation from
  the plan's literal wording) — since its fragility is now fixed at the source (self-locating
  via `BASH_SOURCE`), keeping one correct shared implementation is simpler than duplicating
  the repo-root calculation across 8 call sites.

### 3.3 Merge duplicated shell-agnostic setup
- Re-investigation during implementation found the situation had already partly resolved
  itself in an earlier session: `shell/sh/005-application-settings.sh` turned out to already
  be sourced by **both** `.bashrc` and `.zshrc` — meaning it already was the "one shared
  file" the plan wanted; it just wasn't being treated as authoritative.
- [x] The actual fix: removed the duplicate sccache/delta/wt blocks from
      `shell/zsh/002-application-settings.zsh` (they were redundantly redoing exactly what
      `shell/sh/005-application-settings.sh` already sets up for that same zsh session).
      `shell/zsh/002-application-settings.zsh` now only holds what's genuinely zsh-specific
      (zoxide's `--cmd cd zsh` init, thefuck's alias eval).
- Kept `shell/sh/*` as a directory name even though it's bash/zsh-syntax, not POSIX `sh` —
  renaming it is a bigger, purely-cosmetic disruption (touches the `.bashrc`/`.zshrc` source
  loops and every script's own path-relative assumptions) that wasn't asked for here.

### 3.4 Backup script
- [x] `setup/utils/backup.sh` implemented for real: given a path, backs it up to
      `~/.dotfiles-backup/<run-timestamp>/<same-relative-path>` (move, not copy) unless it
      doesn't exist, is already a symlink into this repo, or is an empty directory (both of
      which are safe to skip backup for and just remove/overwrite).
- [x] Wired into `install.sh`'s per-app symlink loop and `config/.config/zsh/setup.sh`'s
      profile-dotfile symlinks.
- Retention is intentionally indefinite (per the plan's own recommendation, since disk space
  isn't a real constraint here) — no automatic pruning was added.
